Назначение

Скрипт автоматизирует создание тестовых кейсов БКАС. Из исходного кода он собирает готовый пакет кейса и сам проверяет, что кейс корректен: отличает верный ответ агента от неверного и воспроизводимо собирается.

Автор: [Георгий, фамилия].

Вход и выход

Что это
На входеИсходник с дефектным кодом (папка или diff), имя кейса, язык, банковский домен, ссылка на источник, базовый образ по дайджесту. Для модельного шага — дополнительно исправленный код (по желанию).
На выходеПапка готового кейса: instruction.md, task.toml, environment/ (Dockerfile, requirements.txt, исходник), tests/ (test.sh, тесты, схема ответа), solution/solve.sh с эталонным ответом. Рядом — папка eval/ с контрольными ответами и отчёт проверки: прошёл кейс или что в нём сломано.

Что делает скрипт

  1. Собирает пакет кейса. Структура, Dockerfile с базовым образом по дайджесту, зависимости с версиями и хешами, test.sh с подсчётом reward, task.toml с метаданными, хеши входных файлов, списки fail_to_pass и pass_to_pass по факту собранных тестов.
  2. Генерирует задание для агента из того же файла, по которому работают проверки. Скрытых требований в кейсе не возникает.
  3. Заполняет содержательную часть с помощью модели (любая модель с OpenAI-совместимым API, в ВАРМ — MiniMax, GLM): перечень дефектов в коде, признаки для их распознавания и эталонный ответ. Модель пишет только данные, тесты не пишет. Результат проходит те же проверки, при несоответствии — до трёх раундов исправления.
  4. Проверяет собранный кейс. Из эталона автоматически порождает 13 заведомо неверных ответов и 6 верных в другой форме, ещё один верный пишется вручную. Неверные обязаны получить 0, верные — 1. Если нет, указывает, что именно сломано.
  5. Проверяет запуск — эмулирует test.sh без Docker или прогоняет кейс в Docker так же, как при приёмке.
  6. Валидирует кейс на соответствие стандарту БКАС.

Только стандартная библиотека Python 3.8+, установка пакетов не требуется, переносится копированием папки.

Как запустить

Инструкция — файл ЧИТАТЬ_ПЕРВЫМ.md в приложенном архиве, в папке logi — выводы каждого шага для сверки.

python bkas.py doctor
python bkas.py new --from <исходник> --name <имя> --language <язык> --bank-domain <домен> --source-ref <ссылка> --base-image <образ@sha256:...>
python bkas.py draft <кейс> --send --run
python bkas.py run <кейс> --mode fast
python bkas.py eval <кейс> --mode docker

Ограничения

  • Что дефект действительно следует из кода, подтверждает человек.
  • Поддерживаются кейсы вида «разбор кода», тип «почини код» пока нет.
  • Прогон в Docker на ВАРМ — после получения стенда.
